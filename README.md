# KingdomAI — הארכיון החכם של ממלכת אלתריה

פרויקט RAG מקומי בעברית לפי `CODEX_PLAN_KingdomAI_RAG.md`: Python, LlamaIndex, ChromaDB, Gemini API ו־Streamlit. מקור הידע היחיד למענה יהיה 19 מסמכי Markdown מקוריים של ממלכת אלתריה הבדיונית, `ALT-01` עד `ALT-19`.

## מצב המימוש

מומשו שלבים 1–6: הכנת המקורות, אינדוקס מתמשך, אחזור, שירות תשובות עם בדיקת מקורות, ממשק Streamlit וכלי הערכה. קיים אינדקס Gemini חי ומאומת של 19 מסמכים ו־137 מקטעים. **בדיקות האחזור החיות הושלמו לכל 45 השאלות ללא שגיאות; בדיקות נכונות התשובות החיות עדיין לא אושרו עקב כשלים בשירות הניסוח.** בדיקות השיחה עם שירותי דמה עברו. תוצאה זו אינה אישור שכל קריטריוני הקבלה עברו.

נקראו התוכנית המלאה וקובץ `00_קראו_תחילה.md` שבארכיון. הועתקו רק 19 מסמכי Markdown המקוריים ל־`knowledge_base/`; שני קובצי ההערכה הועתקו ל־`eval/`. כל 21 הקבצים הושוו למקור ונמצאו זהים בבייטים. עותקי TXT, README ומניפסט של הארכיון לא הועתקו לתיקיות אלה.

אינדקס הבדיקה כולל גם הוא 137 מקטעים מתוך 19 המסמכים, ונשמר בנפרד ב־`storage/offline/`. אינדקס Gemini נמצא ב־`storage/chroma/` עם מניפסט ב־`storage/index_manifest.json`. שירות השאלות זמין דרך Streamlit, API מקומי ופקודת שורת פקודה. הדוח העדכני: [שלב 6 ותוצאות הקבלה](STEP_6_REVIEW.md). דוחות קודמים: [תיקון מכסות](QUOTA_FIX_REVIEW.md) ו־[שלב 5](STEP_5_REVIEW.md).

## דרישות והתקנה ב־Windows / PowerShell

נדרשת Python 3.11 ומעלה. סביבת העבודה שנמצאה היא Python 3.12.9; הפקודה `python` זמינה, אך משגר `py` אינו מזהה גרסאות מותקנות. לכן ההוראות משתמשות ב־`python` ובנתיב מפורש לסביבת הפרויקט.

מתיקיית האב של הפרויקט:

```powershell
Set-Location .\kingdomai-bot
python --version
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

אם `.venv` כבר נוצרה, אין צורך ליצור אותה שוב. אין צורך להפעיל `Activate.ps1`, משום שכל פקודה מפנה ישירות ל־Python של הפרויקט.

כל תשע התלויות הישירות ב־`requirements.txt` מקובעות לגרסאות שהותקנו ונבדקו בפועל. `requirements.lock.txt` שומר גם תמונת מצב של 141 התלויות המותקנות לצורך שחזור סביבת Windows / Python 3.12.9; לשחזור זה אפשר להתקין ממנו במקום מקובץ הדרישות הישירות. תאימות לגרסאות Python אחרות המותרות בתוכנית טרם נבדקה.

צרו קובץ הגדרות מקומי רק אם אינו קיים:

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
notepad .env
```

הכניסו מפתח Google באופן מקומי בלבד לשדה `GEMINI_API_KEY`. **המפתח נדרש כעת לבדיקת חיבור חי:** יצירת וקטורים למסמכים באינדקס Gemini, וקטור לשאלה וניסוח תשובה באמצעות Gemini. חלוקה מקומית, בדיקות Offline ופיתוח הממשק יכולים להתבצע ללא מפתח. הערך לדוגמה נחשב למפתח חסר. אין להדביק מפתחות בצ'אט, בקוד, במסמכי ידע או ב־Git. `.env`, סביבת Python, לוגים והאינדקס המקומי מוחרגים ב־`.gitignore`. הקוד אינו משנה מסלול חיוב או מכסות באופן אוטומטי.

משך ההמתנה לניסוח מוגבל וניתן להגדרה משום שה־SDK מעביר אותו גם כמגבלת זמן לשרת. [תיעוד השגיאות של Google](https://ai.google.dev/gemini-api/docs/api-errors) מתאר הגדלת deadline כאפשרות לבדיקת `504`; הארכה ל־120 שניות לא פתרה את הכשל בהרצות שלנו. רמת החשיבה ברירת המחדל היא `medium`, לפי [המודל המוגדר בתיעוד Google](https://ai.google.dev/gemini-api/docs/latest-model). גם ניסוי נפרד ב־`low` נכשל בזמן המתנה; הוא לא שינה את ברירת המחדל או את `.env` המקומי.

`config.py` טוען `.env` בקידוד UTF-8, כולל BOM. משתני סביבה גוברים על הקובץ; נתיבים יחסיים נפתרים מול שורש הפרויקט ולא מול תיקיית ההפעלה. הנתיבים של מקורות, הערכה ואינדקס חייבים להיות נפרדים וללא קינון זה בתוך זה. מוגדרים ערכי גודל וחפיפה תקינים, Top-K בין 1 ל־5 וסף Cosine תקין אם הוזן. טעינת ההגדרות אינה כותבת קבצים, פונה ל־Google או בונה אינדקס, ואינה נכשלת רק משום שחסרים מפתח, מסמכים או אינדקס; מצבים אלה מדווחים בנפרד.

## הכנת הארכיון — שלב 2

הכלי מקבל ZIP או תיקייה מחולצת. להרצה על הקובץ שסופק בסביבת העבודה הזאת:

```powershell
$archivePath = Join-Path $env:USERPROFILE 'Downloads\KingdomAI_%D7%9E%D7%90%D7%92%D7%A8_%D7%9E%D7%9E%D7%9C%D7%9B%D7%AA_%D7%90%D7%9C%D7%AA%D7%A8%D7%99%D7%94_RAG.zip'
& .\.venv\Scripts\python.exe -X utf8 -m scripts.prepare_knowledge --source $archivePath
```

אפשר להעביר ב־`--source` גם את הנתיב לתיקייה המחולצת המכילה את `01_מסמכים_Markdown` ואת `03_בדיקות_ללא_העלאה_ל_RAG`, או את תיקיית האב שלה. ללא `--source`, הכלי מחפש בשורש הפרויקט מקור מתאים יחיד; אם אין מקור או יש כמה, הוא מחזיר שגיאה מפורשת. בהרצה לעיל נעשה שימוש בקובץ שב־Downloads, ואין צורך להעתיק את ה־ZIP לפרויקט.

הכלי מאמת את כל קלט המקור ואת שני היעדים לפני העתקה. הוא בודק בדיוק 19 מזהים ייחודיים `ALT-01`–`ALT-19`, התאמה בין שם הקובץ למזהה שבגופו, קידוד UTF-8/BOM, כותרת ותוכן לא ריק. הנתונים מועתקים ללא שינוי בבייטים, כולל BOM וסיומות שורה אם קיימים. שאלות ההערכה ומפתח התשובות נבדקים למבנה של 45 רשומות תואמות ולמקורות תקינים, ונשמרים בנפרד.

אין חילוץ כללי באמצעות `extractall`: רק הקבצים שנבחרו נקראים מה־ZIP ונכתבים בשמות קבצים מאומתים. נחסמים נתיבי מעבר, נתיבים מוחלטים, שמות Windows לא תקינים, קישורים, כפילויות ומקורות עמומים. קבצים זהים ביעד נשארים ללא שכתוב; קובץ קיים שתוכנו שונה או קובץ לא צפוי עוצרים את ההכנה לפני העתקה. בכשל כתיבה הכלי מנסה להסיר רק קבצים חדשים שיצר ומדווח במפורש אם הניקוי נכשל.

## אינדוקס מתמשך — שלב 3

לבניית אינדקס Gemini נדרש מפתח מקומי ב־`.env`. ההרצה שולחת רק מקטעים מתוך 19 מסמכי המקור ל־Gemini Embeddings:

```powershell
& .\.venv\Scripts\python.exe -X utf8 -m scripts.ingest --rebuild
```

להרצה חוזרת שמאמתת את האינדקס הקיים ומשתמשת בו ללא יצירת וקטורים מחדש:

```powershell
& .\.venv\Scripts\python.exe -X utf8 -m scripts.ingest
```

אם אין אינדקס או ששונו המקורות, מודל ה־Embedding, הממד, הגדרות החלוקה, נתיב המסד או גרסאות הספריות המתועדות, מתקבלת שגיאה ונדרש `--rebuild` מפורש. אין מעבר אוטומטי למודל אחר או למצב Offline. בהיעדר מפתח API, בנייה רגילה נעצרת לפני יצירת מסד או נעילה. אין שינוי אוטומטי של מכסות או מסלול תשלום.

לבדיקת התשתית ללא מפתח ורשת, יש לבחור במפורש במצב הבדיקה:

```powershell
& .\.venv\Scripts\python.exe -X utf8 -m scripts.ingest --offline --rebuild
& .\.venv\Scripts\python.exe -X utf8 -m scripts.ingest --offline
& .\.venv\Scripts\python.exe -X utf8 -m scripts.check_setup --offline
```

| מאפיין | אינדקס Gemini רגיל | אינדקס בדיקה Offline |
|---|---|---|
| מודל פעיל | `gemini-embedding-001` | `kingdomai-offline-hash-v1` |
| ממד פעיל | 3072 כברירת מחדל, ניתן להגדרה | 64 |
| מסד | `storage/chroma/` כברירת מחדל | `storage/offline/chroma/` |
| מניפסט | `storage/index_manifest.json` | `storage/offline/index_manifest.json` |
| אוסף | `kingdomai_altheria_docs` כברירת מחדל | `kingdomai_altheria_docs_offline` |
| מה נבדק כאן | אינדוקס חי של 137 מקטעים, התאוששות מ־429, אימות וטעינה חוזרת; עדיין אין תשובה חיה תקינה | בנייה אמיתית ב־Chroma, התמדה, טעינה חוזרת ו־Rebuild |

וקטורי ה־Offline מחושבים באופן דטרמיניסטי לצורך בדיקת אחסון. הם אינם Embeddings סמנטיים ולא מודדים את איכות האחזור או התשובות. המניפסט מסמן את המודל הפעיל, הממד ואת `offline=true`; הגדרות Gemini המבוקשות נשמרות בשדות נפרדים ואינן מוצגות כמודל שביצע את האינדוקס. גם בהגדרות נתיבים מותאמות, הכלי חוסם התנגשות בין מסד הבדיקה, המסד הרגיל, מסמכי הידע וחומרי ההערכה.

### חלוקה, מקורות ומניפסט

`SentenceSplitter(chunk_size=512, chunk_overlap=64)` פועל עם הטוקנייזר המצורף ל־LlamaIndex. החלוקה שומרת תחילה על גבולות כותרות Markdown; בתוך סעיף נשמרת חפיפה של עד 64 טוקנים לפי גבולות המשפטים. סעיפים קצרים נשארים קצרים, ואין כפייה של חפיפה בין סעיפים. המסמכים אינם מסוכמים או משוכתבים.

לכל מקטע נשמרים מזהה ALT, שם קובץ יחסי, כותרת, סוג, תקופה, נושאים, סעיף מקורי, חתימת תוכן ומזהה מקטע דטרמיניסטי. קשר המקור של LlamaIndex מצביע תמיד למזהה `ALT-XX`. שדות תצוגה ארוכים נשמרים במסד אך אינם נספרים מחדש בטקסט שנשלח ל־Embedding; כותרת, מזהה וסעיף כן נכללים. נבדקת מגבלת 512 הטוקנים כולל מטאדאטת ה־Embedding.

Chroma מוגדר עם Cosine וללא פונקציית Embedding אוטומטית משלו; כל הווקטורים מסופקים במפורש. Gemini מקבל `RETRIEVAL_DOCUMENT` למסמכים ו־`RETRIEVAL_QUERY` לשאלות דרך ה־adapter, ממד מפורש ומספר ניסיונות מוגבל. מצב Vertex שמופעל ממשתנה סביבה נחסם כדי למנוע שינוי ספק סמוי.

המניפסט כולל את חתימות 19 קובצי המקור, גרסת המאגר, פרטי המודל והממד, הגדרות החלוקה, נתיב ואוסף Chroma, מספרי מסמכים ומקטעים, גרסאות ספריות ומזהה דור האינדקס. האימות בודק גם את תוכן האוסף בפועל, המטאדאטה, הממד, ה־Cosine ומזהי המקטעים.

### בנייה מחדש ושחזור כשל

הבנייה משתמשת בנעילה ובאוסף זמני שבבעלות הפעולה. כשל ב־Embeddings אינו מחליף את האינדקס הקיים. רק לאחר שמירת כל המקטעים ואימותם מקודם האוסף הזמני ונכתב המניפסט בהחלפה אטומית; כשל רגיל בשלב זה משחזר את האוסף הקודם. אוספים אחרים אינם נמחקים. המנגנון אינו מוחק את תיקיית Chroma כולה.

כל אצווה מוצלחת של עד עשרה מקטעים נשמרת כעת מיד ובאופן אטומי תחת `storage/embedding_checkpoints/`. מצב Offline שומר בנפרד תחת `storage/offline/embedding_checkpoints/`. הקובץ מכיל וקטורים ומזהי מקטעים, ללא מפתח API או טקסט המקורות. התאמה נבדקת לפי הגדרות האינדקס, המודל, הממד, המקורות והקלט המדויק ל־Embedding. קובץ פגום עוצר את הבנייה במפורש.

אם מתקבלת שגיאת מכסה, לאחר שהמכסה מאפשרת להמשיך מריצים **אותה פקודה**:

```powershell
& .\.venv\Scripts\python.exe -X utf8 -m scripts.ingest --rebuild
```

הכלי מציג כמה מקטעים נטענו משמירה וכמה נותרו, ושולח רק את החסרים. `--rebuild` בונה מחדש את אוסף Chroma, אך משתמש בווקטורים תואמים שכבר נשמרו. אין צורך למחוק מסד, ליצור מפתח אחר או לשנות חיוב. כדי ליצור גם את הווקטורים מחדש בכוונה מפורשת, ניתן להוסיף `--fresh-embeddings`; פעולה זו שולחת שוב את כל המקטעים ולכן אינה פתרון למגבלת מכסה.

**הניסיון הישן שנעצר ב־100/137 קדם לתיקון:** הווקטורים בו נשמרו בזיכרון בלבד, ולכן לא ניתן לשחזר אותם לאחר סיום התהליך. הניסיון הראשון עם התיקון מתחיל מאפס אם אין קובץ התקדמות תואם. מרגע שהתקדמות נשמרה, ניתן להמשיך ממנה גם לאחר סגירת התהליך. אינדוקס חלקי אינו אינדקס לשאלות; אם אין אינדקס מלא קודם, `scripts.ask` מסביר שהאינדוקס טרם הושלם.

ברירות המחדל לבקשות האינדוקס החי הן מרווח של שש שניות בין תחילת בקשות, ועד שני ניסיונות חוזרים לכל אצווה בשגיאת `429`. זמן ההמתנה מכבד את ההנחיה המובנית של הספק ואת `Retry-After`, עם השהיה מדורגת; אם נדרשת המתנה מעל 60 שניות, או שהספק מציין מכסה יומית או מכסה אפס, הפעולה נעצרת ושומרת התקדמות. מגבלה לא מזוהה אינה מסומנת אוטומטית כמכסה יומית. מרווח הבקשות מפחית עומס ואינו מבטיח זכאות או מכסה מספקת.

ניתן להגדיר ב־`.env` המקומי, ללא שינוי המפתח:

```dotenv
EMBEDDING_REQUEST_INTERVAL_SECONDS=6
EMBEDDING_MAX_RETRIES=2
EMBEDDING_MAX_RETRY_WAIT_SECONDS=60
```

הטווחים המותרים הם 0–60 שניות למרווח ולהמתנה, ו־0–5 ניסיונות חוזרים. בהיעדר השדות האלה נשמרות ברירות המחדל, ולכן אין חובה לשנות `.env` קיים. המכסות בפועל הן של פרויקט Google ותלויות במודל ובחשבון; ניתן לבדוק אותן ב־[AI Studio](https://aistudio.google.com/rate-limit?timeRange=last-28-days) וב־[תיעוד המכסות הרשמי](https://aistudio.google.com/docs/rate-limits). אין ניסיון לעקוף מגבלה או להפעיל חיוב אוטומטי.

אין עסקה אחת שמשותפת ל־Chroma ולקובץ JSON. לכן הפסקת תהליך פתאומית עשויה להשאיר נעילה או אוסף זמני/גיבוי. מזהי הדור נבדקים לפני שימוש באינדקס כדי לחסום מצב לא תואם. במקרה כזה יש לבדוק את הפעולה שנקטעה ואת הנעילה לפני הסרתה והרצת Rebuild; אין ניקוי אוטומטי של קבצים או אוספים לא מזוהים.

## שירות שאלות ותשובות — שלב 4

לאחר הגדרת המפתח, יש לבנות את אינדקס Gemini פעם ראשונה, או אחרי שינוי שמחייב Rebuild, ולשאול שאלה:

```powershell
& .\.venv\Scripts\python.exe -X utf8 -m scripts.ingest --rebuild
& .\.venv\Scripts\python.exe -X utf8 -m scripts.check_setup
& .\.venv\Scripts\python.exe -X utf8 -m scripts.ask --question 'מהם שבעת בתי החותם?'
```

בשאלות נוספות מריצים רק `scripts.ask`, ללא בנייה מחדש. `check_setup` מאמת מקומית את המבנה ואינו מבצע בקשת בדיקת הרשאות ל־Gemini. בלי מפתח, `scripts.ask` מחזיר הודעה בעברית עם הנחיה ל־`.env`, קוד יציאה 2 וללא מקורות או תשובה מדומה. קוד 0 פירושו פעולה שהסתיימה עם תשובה או סירוב תקין; שגיאת קלט או שירות מחזירה 2.

אם Gemini מחזיר `504`, מוצגת כעת הודעה שהשירות לא השלים את הבקשה בזמן, עם הצעה לנסות שוב את השאלה מאוחר יותר. האינדקס המלא נשאר זמין. בבדיקה החיה קוד זה אומת באמצעות סוג השגיאה וקוד מספרי בלבד, ללא הדפסת הודעת SDK או פרטי חשבון. לא הוחלף המודל בעקבות הכשל.

`ArchiveRetriever` טוען אינדקס קיים ומאומת ומשתמש ב־`VectorStoreIndex.from_vector_store` עם מודל Embedding מפורש ו־`similarity_top_k=5` כברירת מחדל. רק השאלה המקורית עוברת Embedding בזמן השאלה; אין הרחבת שאילתה, Reranking או יצירת וקטורים מחדש למסמכים. נשמרים עד חמישה מקטעים, כולל כמה מקטעים מאותו מסמך אם אוחזרו. שינוי מקור, מניפסט או דור אוסף עוצר שימוש בשירות הישן ומחייב טעינה מחדש.

ציון ה־adapter המותקן מומר מ־`exp(-distance)` לדמיון Cosine בעזרת `1 + log(score)`, ונבדק מול המרחק הגולמי של Chroma. `SIMILARITY_THRESHOLD` נשאר ריק; אם יוגדר אחרי כיול, הוא יחול על Cosine ולא על הציון המומר של הספרייה. ציון דמיון אינו הסתברות לנכונות תשובה.

שירות התשובות שולח הודעת מערכת נפרדת ונתוני JSON עם השאלה והמקטעים בלבד. אין בו מפתח תשובות, גישה לאינטרנט, כלי חיפוש או היסטוריית שיחה כמקור ידע. אם לא אוחזרו מקטעים, מוחזר סירוב קבוע ללא הפעלת מודל הניסוח. אחרת Gemini נדרש להחזיר טענות בעברית עם ראיות מזוהות וציטוטים מדויקים.

הניסוח מוגדר ללא המשך אוטומטי של יצירה וללא קריאות פונקציה אוטומטיות. ניסיון יחיד מוגדר גם ב־SDK וגם ב־adapter של הניסוח; כשל שירות מוחזר למשתמשת במקום להפעיל לולאת יצירה או ניסיונות נוספים ברקע.

לפני הצגת תשובה נבדקים מבנה JSON, מזהי המקטעים, שפת הטענות, מגבלות אורך, ציטוטים רציפים שקיימים במקור והיעדר הפניה למקור שלא צוטט. מספר בספרות חייב להופיע בראיה, בכותרת או בתקופה של המקור המצוטט. לכן יש לשמר ייצוג מילולי של מספר כשכך נכתב במקור. שם המקור והסעיף מגיעים מהמטאדאטה, ולא מטקסט שהמודל המציא. פלט כלי, מקורות או ציטוטים לא תקינים אינם מוצגים כתשובה.

המדיניות דורשת להבדיל בין דוח ראשוני להכרעה מאוחרת לפי תוכן, סוג ותאריך, ובין הצעה או התחייבות לבין ביצוע. טענה שמבוססת רק על מסמך המסומן כראשוני חייבת לתאר אותו ככזה; תשובה הנשענת רק על דיווחים ראשוניים מסומנת כחלקית. אין קביעה של סמכות לפי מספר ALT או השלמת עובדות ממקור שלא אוחזר.

**מגבלה:** ציטוט מדויק אינו מוכיח לוגית שהניסוח נובע ממנו. הבדיקות המבניות והמדיניות מקטינות טעויות, אך אינן מבטיחות אפס הזיות או עמידות מלאה בפני Prompt Injection. בדיקות הדמה בוחנות את גבולות התוכנה; בדיקת רלוונטיות, הסקה וסתירות ב־Gemini חי עדיין דורשת מפתח והרצה על שאלות ההערכה.

"האינדקס מוכן לחיפוש" מציין אימות מקומי; החיבור וזמינות השירות של Gemini נבדקים בעת שליחת שאלה.

המפתח נקרא מ־`.env` המקומי, ללא הצגתו בממשק. פתיחת הדף, רענון וניקוי שיחה אינם מפעילים את Gemini ואינם יוצרים וקטורים למסמכים. שירות השאלות נשמר בנפרד לכל Session ומשמש שוב בין רענונים. כל שאלה מקורית מועברת בפני עצמה ל־`QAService.ask`; ההיסטוריה מיועדת לתצוגה ואינה נשלחת כמקור ידע. עד עשרים שאלות ותשובות אחרונות נשמרות בזיכרון ה־Session בלבד, ללא קובץ היסטוריה.

## כלי ההערכה — שלב 6

הכלי שולח לשירות רק את השאלה המקורית. מפתח התשובות נשאר מקומי להשוואה. קוד יציאה `0` מציין השלמת השאלות שנבחרו ותקינות אבחוני המבנה, **ולא ציון נכונות סמנטית**; קוד `2` מציין כשל, שאלות שלא הורצו או אי־תקינות באבחון. `error` אינו סירוב מחוסר ידע, ו־`not_run` אינו בדיקה שעברה. בבקשת מענה הדוח שומר את הראיות מאותה קריאה, ללא שאילתת אחזור נוספת.

בשלב 5 נוספו **38 בדיקות**: 26 לפעולות הממשק ו־12 למוכנות המקורות והאינדקס. בהרצת החבילה המלאה: **386 עברו, אחת דולגה ו־67 אזהרות Chroma, ב־162.63 שניות**. בדיקות AppTest מכסות שימוש חוזר בשירות, שאלות מקוריות, מקורות, סירוב, שגיאות, הגבלת היסטוריה, הפרדת Sessions, ניקוי, שינוי הגדרות והצגה בטוחה. בדיקות מוכנות כוללות Chroma אמיתי בנתונים סינתטיים בתיקיות זמניות, דחיית אינדקס Offline ושינוי מקור בלי שינוי מניפסט. פירוט ומגבלות: [STEP_5_REVIEW.md](STEP_5_REVIEW.md).

לאחר התאמות הפריסה עברו שוב כל 26 בדיקות הממשק. בנוסף נבדקה התצוגה בדפדפן Chrome אמיתי במחשב ובנייד: RTL בתוכן ובשדה השאלה, ללא גלילה אופקית. צילומי המסך מופיעים בדוח שלב 5. בדיקת הדפדפן פתחה את האינדקס הקיים ללא שליחת שאלה ל־Gemini.

בשלב 3 נבנה ונפתח מחדש אינדקס Offline עם 137 מקטעים ייחודיים מ־19 המסמכים. מספר הטוקנים המרבי, כולל מטאדאטת Embedding, היה 508. הרצה ללא `--rebuild` שמרה את האוסף ואת הבייטים וזמן השינוי של המניפסט. נבדקו גם בנייה מחדש ללא כפילויות, שימור אוסף בלתי קשור, כשל Embedding, כשל שמירת מניפסט, שינויים במודל/ממד/מקורות/חלוקה, הפרדת נתיבים והיעדר קריאת חומרי הערכה. בדיקת SDK עם לקוח דמה וחסימת רשת אימתה את ניתוב המסמכים והשאלות ואת התצורה.

בשלב 4 נבדקו אחזור בפועל עם וקטורי דמה, Top-K, המרת Cosine, היעדר קריאת חומרי הערכה, גבולות מקור וציטוט, תגובות דמה סותרות, סירוב ושגיאות API מדומות. ה־LLM adapter האמיתי נבדק מול לקוח SDK מדומה, עם חסימת רשת חיצונית, פלט JSON וללא כלים. אינטגרציה נוספת על אינדקס 137 המקטעים הקיים אחזרה חמישה מקטעים ואימתה ציטוט עם מודל דמה מפורש, בלי שכתוב המניפסט.

45 שאלות ההערכה נבדקו בשלב 2 מבחינת מבנה והתאמה למפתח, ובשלב 6 הורצו כולן מול Gemini Embeddings לאחזור. איכות המענה החי טרם אושרה בגלל הכשלים המתועדים. אין טענה שמודל חי עבר את בדיקות הסתירות או ה־Prompt Injection.

התוכנית בוחרת במודלים [Gemini 3.8 Flash](https://aistudio.google.com/docs/models/gemini-3.8-flash) ו־[Embeddings](https://aistudio.google.com/docs/embeddings). `gemini-embedding-001` נבדק באינדוקס חי וב־45 שאילתות ההערכה. מודל הניסוח מזוהה בחשבון ותומך ב־`generateContent`, אך הבדיקות לא הסתיימו בתשובה תקינה. מכסות, זכאות ועלויות בפועל תלויות בחשבון ובתנאי הספק; ראו [תמחור רשמי](https://aistudio.google.com/docs/pricing). לא הופעל חיוב או שינוי מסלול.

ממשקי הספריות: [LlamaIndex GoogleGenAI](https://developers.llamaindex.ai/python/framework-api-reference/llms/google_genai/), [GoogleGenAIEmbedding](https://developers.llamaindex.ai/python/framework-api-reference/embeddings/google_genai/) ו־[Chroma collection configuration](https://docs.trychroma.com/docs/collections/configure). אלה אסמכתאות לפיתוח התוכנה בלבד, ואינן נשלחות לבוט כידע על אלתריה.
